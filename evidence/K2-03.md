# K2-03. Compose и сохранность данных

Группа: ФЭ-9.24.1

## Команды и результат

Скопировала настройки в `compose.student.yaml` и указала для `api` и `web` свой образ `devops-student:v1`. Выполнила `docker compose stop`, проверила файл командой `docker compose -f compose.student.yaml config`, затем запустила `docker compose -f compose.student.yaml up -d`. Оба контейнера стали `healthy`.

Через страницу отправила заявку **№5** («Не заряжается»). Затем выполнила `docker compose -f compose.student.yaml up -d --no-deps --force-recreate api`. После готовности API заявка №5 осталась в списке. Отправила ещё одну заявку **№6** («Не запускается программа»); она тоже появилась в списке.

## Как это работает

`web` обращается к `api` по адресу `http://api:8000`: `api` — имя сервиса внутри сети Compose, 8000 — порт приложения внутри контейнера. В браузере я открываю `localhost:8080`, потому что настройка портов связывает 8080 на MacBook с 8000 у `web`. Том `requests` хранит заявки отдельно от контейнера `api`, поэтому замена контейнера не удалила заявку №5. Если бы база лежала только внутри контейнера, при его пересоздании данные могли бы пропасть.

Для повторного запуска из папки проекта: `docker compose -f compose.student.yaml up -d`, затем открыть `http://localhost:8080`.
